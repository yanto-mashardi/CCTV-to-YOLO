# Setup (draft, not deployed)
1. Run server/preflight.sh on VPS; inspect existing services, firewall and ports. Do not stop or replace ETA-ETD. If ports conflict, use different host ports or audit existing MediaMTX before reusing it.
2. Confirm Docker Compose is installed. Copy server/mediamtx.yml.example to server/mediamtx.local.yml, replace all three placeholders with distinct strong URL-safe passwords. Never commit local configuration. Verify image tag and configuration compatibility in a local test first.
3. From server directory: docker compose -p cctv-yolo config; then only after approval docker compose -p cctv-yolo up -d. Check docker compose -p cctv-yolo logs. Allow TCP publisher/reader ports in provider and host firewall as appropriate. Restrict source IP when feasible; Docker published ports may bypass UFW. RTMP and RTSP are plaintext by request.
4. OBS custom server: rtmp://VPS:1935 ; stream key bengkalis?user=bengkalis_pub&pass=PASSWORD. Larix URL: rtmp://VPS:1935/pakning?user=pakning_pub&pass=PASSWORD. Verify exact URL behavior for each publisher. VLC: rtsp://campus_reader:PASSWORD@VPS:8554/bengkalis (or pakning). Verify anonymous and wrong path denied.
5. Campus Windows: cd client; py -m venv .venv; .venv\Scripts\python -m pip install -r requirements.txt; copy config.example.json config.local.json. Set BENGKALIS_RTSP and PAKNING_RTSP environment variables to authenticated URLs. Use .venv\Scripts\python main.py --camera all. Run tests with .venv\Scripts\python -m unittest test_counting.
6. Calibrate each normalized line against actual camera view and direction before collecting real data. Default line is illustrative; source_status SIMULATION must be kept for test footage. Set OBSERVED only for verified live observations.
7. Each crossing writes JSONL and CSV immediately to output/<port>. JSONL is primary, CSV rebuilt on restart. Totals are cumulative over the local journal; one process per camera. Timestamp is campus frame receipt/processing time, not synchronized camera capture time. Track identity resets on reconnect; crossings during outages can be missed and duplicates across sessions remain possible. Connection log records disconnects. A production release needs stale track cleanup, health supervision, crash recovery for a partial journal line, latency measurement, and manual ground truth validation.
8. No ETA-ETD integration. No video recording or YOLO on VPS. Rollback new standalone relay only: docker compose -p cctv-yolo down. Never use docker system prune or stop unrelated containers.
